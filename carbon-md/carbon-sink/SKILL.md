# Carbon Sink  碳汇项目开发（林业/海洋/草地）

## Overview

支持林业、海洋（蓝碳）、草地等生态系统碳汇项目的固碳量核算与开发。核心：匹配碳汇方法学 → 核算碳汇量（CO2 吸收 − 排放源）→ 编制项目文件 → 对接 CCER/碳汇交易。碳汇与 `ccer-development` 衔接，碳汇量核算与 `carbon-accounting` 的 GWP 交叉核对。

本 Skill 为**数据驱动模式**：CCER 制度依据与政策适用性从 `data/` 政策元数据表查询；碳汇计量因子优先从因子库查询，数据层暂无 LULUCF/林业碳汇分库时回退 `references/sink-guide.md` 历史参数并显式标注。

## 数据层（项目开发前必读）

CCER 制度依据与政策适用性从 `data/` 数据层动态查询；项目排放侧因子（化石燃料、电力等）从排放因子库查询。碳汇计量参数（生物量扩展因子、根冠比等 LULUCF 参数）数据层暂无对应分库，回退 `references/sink-guide.md` 并标注。

| 内容 | 数据文件 | 统一查询命令 |
|---|---|---|
| 政策元数据表（CCER 管理办法、碳汇方法学政策依据） | `data/policy/policy_metadata.json` | `python data/scripts/query_data.py search-policy <关键词>` |
| 化石燃料因子库（项目排放侧） | `data/factors/fossil_fuel_factors.json` | `python data/scripts/query_data.py get-fuel-factor <燃料类型>` |
| 电网排放因子库（项目排放侧） | `data/factors/grid_electricity_factors.json` | `python data/scripts/query_data.py get-grid-factor --year <年份> --region <区域>` |
| 数据版本号 | — | `python data/scripts/query_data.py version` |

> 运行路径：在 `carbon-md/` 根目录下执行上述命令。

数据状态约定：数据层每条记录含 `confidence` 或 `status` 字段，引用时必须透传，不得把估算/占位当已查证输出。碳汇计量参数数据层暂无 LULUCF 分库，回退 references 历史参考值并标注。

## Workflow

### 1. 确认项目类型、地块、地区与计入期
- 确认碳汇类型：林业（造林、再造林、森林经营）、海洋（红树林、海草床等蓝碳）、草地。
- 确定项目地块、所在地区、计入期长度与起始年。

### 2. 从政策表查询 CCER 制度依据
- 执行 `python data/scripts/query_data.py search-policy 自愿减排` 和 `python data/scripts/query_data.py search-policy CCER`，获取《温室气体自愿减排交易管理办法》作为项目审定、减排量核证与交易的顶层制度依据，透传真号、日期、时效状态与数据状态。
- 方法学适用性（造林碳汇、红树林营造修复等首批 CCER 方法学）：先查政策表/行业规则表；**数据层暂无碳汇类具体方法学条目**，回退 `references/sink-guide.md` 与 `references/standards-sources.md` 对照边界、计入期与碳库要求，并标注"方法学为 legacy 参考，以生态环境部最新发布方法学原文为准"。

### 3. 查询碳汇计量因子（query_factor，查不到则 legacy 回退）
- 项目活动产生的化石燃料、运输、外购电力等**排放侧因子**，用 `query_factor(行业=..., 能源类型=..., 年份=..., 地区=...)` 从因子库查询（如原煤、柴油、电力）。
- **碳汇计量参数**（生物量扩展因子 BEF、根冠比、含碳率、木材密度、土壤有机碳密度等 LULUCF 参数）：数据层 emission_factors 库暂无 LULUCF 分库，回退 `references/sink-guide.md` 历史参考值，并在输出标注"legacy 回退；应优先采用项目所在区域/同类林分实测数据"。
- 碳质量→CO2 折算采用物理常量 44/12（脚本内置，非数据层参数）。

### 4. 执行碳汇量核算（scripts/sink_calc.py）
- 使用 `scripts/sink_calc.py`：碳汇量 = 项目碳库增量 − 基线碳库增量 − 项目排放 − 泄漏。
- 传入上一步确定的项目/基线/排放/泄漏量；`--policy` 模式可同时打印 CCER 制度依据（数据层查询）。

### 5. 输出标注（必做）
- 在输出中标注：**CCER 制度依据文号与日期**（部令第31号，来自政策表及数据状态）、**采用方法学名称与版本**（注明 legacy 参考 + 最新方法学原文核验）、**排放因子来源**（机构+年份+数据状态，数据层/legacy 回退）、**碳汇计量参数来源与本地化程度**。

## 规范
- 碳汇方法学与参数（含生物量、根冠比、含碳率）须用最新官方/权威来源，注明年份；政策依据文号以 `_data` 政策元数据表为准。
- 避免重复计入（同一碳库不得跨项目重复核算）。
- 涉及实地碳汇开发，建议专业机构与现场核查介入。

### 质量保证与数据规范
- **碳库完整性原则**：按方法学要求纳入全部碳库（地上生物量、地下生物量、枯落物、枯死木、土壤有机碳等），排除项需说明理由。
- **参数本地化原则**：生物量扩展因子、根冠比、含碳率、土壤碳密度等关键参数优先采用项目所在区域或同类林分/植被的实测数据；数据层 legacy 回退值仅作占位，不得直接当作项目参数。
- **基线保守性原则**：基线碳库增量取低值、项目排放与泄漏取高值，确保净碳汇量不被高估。
- **数据可复现原则**：样地调查、遥感解译、模型计算全部留痕，中间数据与参数表可追溯、可复核。
- **长期监测原则**：计入期内监测计划与质量控制流程明确，确保碳库变化数据持续可靠。
- 完成碳汇量核算或项目设计后，应使用 `references/quality-checklist.md` 逐项自检，通过后方可输出。

### 来源与引用规范
- 方法学、参数、排放因子均需标注来源（发布机构、文件名、版本、年份）；政策文号优先透传自 `_data` 政策元数据表记录。
- **实测数据**（现场样地、计量、遥感）与**模型模拟/默认值**严格区分，默认值必须注明出处与适用条件。
- 引用优先级：生态环境部 / 国家林草局 / 自然资源部发布的方法学与指南 > 国家温室气体排放因子数据库 > IPCC 指南 > 中科院 / 高校权威研究 > 学术文献。
- 区域敏感参数（树种、气候带、土壤类型、海拔）必须与项目所在地匹配，不得跨气候带或跨区域套用。
- 标准与数据来源的详细清单参见 `references/standards-sources.md`。

### 边界与免责
- 本 Skill 提供碳汇项目开发的方法指导与初步测算，不替代具备资质的审定核证机构与专业现场调查工作。
- 本 Skill 不构成法律、财务或投资建议；项目能否备案、碳汇量能否签发以主管部门审核为准。
- 本 Skill 不对土地权属、原住民权益、生物多样性影响等法律与社会问题做法律判断，相关问题需专项评估。
- 碳汇项目存在火灾、病虫害、极端气候等自然逆转风险，测算结果未计入该类风险损失。
- 涉及实地调查、土壤采样、遥感解译等专业工作，应由具备相应资质的机构与人员执行。
