# Carbon Policy 双碳政策法规检索与解读

## Overview

结构化检索、定位并解读中国双碳领域的政策法规与标准，向用户输出要点化、可执行的合规解读，而非原文堆砌。核心产出：政策定位（层级/发布机构/生效时间）→ 核心要点 → 对用户主体的影响 → 合规行动清单。

本 Skill 为**数据驱动模式**：政策元数据（文号、发布机关、日期、时效状态、原文链接）优先从 `_data/` 数据层查询，不在本文件写死具体政策编号；数据层未覆盖的政策再走联网核验，并在输出中明确标注数据状态。

## 数据层（检索前必读）

所有政策依据、行业规则均从 `_data/` 数据层动态查询，**不在本 Skill 中写死任何政策文号或行业参数**。新增政策/行业只需在数据层追加记录，无需修改本 Skill 代码。

| 内容 | 数据文件 | 统一查询命令（在 `carbon-md/` 下运行） |
|---|---|---|
| 政策元数据表 | `_data/policy_meta.json` | `python _data/query.py policy --keyword <关键词>` |
| 全部政策清单 | `_data/policy_meta.json` | `python _data/query.py policy`（不带过滤条件即返回全部） |
| 行业规则表 | `_data/industry_rules.json` | `python _data/query.py industry --name <行业名>`（或 `industry <行业代码>`） |
| 三表统计 | — | `python _data/query.py stats` |

> 脚本内统一接入方式：`sys.path.insert(0, str(Path(__file__).resolve().parents[2] / "_data"))` + `from query import query_policy, query_industry`。

数据状态约定：数据层每条记录含 `数据状态` 字段（取值 ∈ {已查证, 估算, 占位-待核实}），输出时必须透传，不得把估算/占位值当已查证值输出；引用时必须透传文号、发文机关、发布日期、时效状态与数据状态。

## Workflow

### 1. 明确检索需求
- 确认用户需要的是：政策原文条款 / 行业适用标准 / 合规义务梳理 / 时间节点，还是对某一政策的影响解读。
- 确认主体类型（控排企业/自愿减排方/咨询机构/个人）与所在行业、地区。

### 2. 数据层优先检索（policy，主入口）
- 先执行 `python _data/query.py policy --keyword <关键词>`，从政策元数据表检索已核实政策元数据（脚本内对应 `query_policy()`）。
- 常用命令组合：
  - 查某行业配额规则：`python _data/query.py policy --type 配额方案 --industry <行业名>`
  - 查 CCER 制度：`python _data/query.py policy --keyword 自愿减排`
  - 查某行业核算指南：`python _data/query.py policy --type 核算指南 --industry <行业名>`
  - 查全部政策清单：`python _data/query.py policy`（不带过滤条件）
- 命中后直接取 **文号 / 发文机关 / 发布日期 / 时效状态 / 原文链接** 作为政策定位依据；**不再凭记忆写死文号**。
- 行业适用性（是否纳入碳市场、配额分配方法、间接排放口径）同时用 `python _data/query.py industry --name <行业名>`（脚本内 `query_industry()`）核对行业规则表。

### 3. 数据层未命中 → 联网核验
- 数据层无对应记录时，再通过 `enterprise_agentic_search`（若企业内部有资料）或 `general_search` + `web_fetch` 抓取原文；法条可走 `seed_legal_search`。
- 权威来源优先：政府官网（国家发改委、生态环境部、工信部）、全国碳排放权交易市场官网、地方政府双碳文件。
- 联网核实到的政策若属高频引用，应在输出中标注"数据层暂无记录，本条为联网核实（待回写数据层）"，避免把临时检索结果当作已核实数据层结论。

### 4. 提取与解读要点
- 用 `references/policy-index.md` 校验政策体系定位（"1+N"体系中的位置）。
- 提取对用户主体有直接约束的条款：配额、核算、MRV、履约、处罚。
- 用 `references/market-rules.md` 对照碳市场交易与履约规则（具体配额方案/抵消比例以数据层配额方案记录为准）。

### 5. 输出合规解读与标注（必做）
- 结构：政策概况（层级/机构/文号/日期）→ 核心要点（分条）→ 对用户的影响 → 需执行的合规动作与时间表。
- **标注要求**：每条政策依据写明 发文机构 + 文号 + 发布/施行日期 + 数据状态（已查证/估算/占位-待核实）；数据层来源注明原文链接。
- 交付形式：要点解读默认走 `lark-doc` 或 `word`；表格对比走 `sheet`；需要图文呈现时配合 `doubao-visualization`。

## 质量保证与数据规范

### 检索质量控制
- **官方原文优先**：政府官网、法规数据库、正式公告为第一来源；二手解读、媒体报道只能辅助理解，不能作为引用依据
- **最新版本优先**：政策会更新、修订、废止，检索时必须确认当前版本是否仍然有效，避免引用已废止的旧政策
- **正式文号为准**：引用时须使用发文机构 + 文号 + 标题 + 发布日期，不能只有俗称或简称
- **多方来源不一致时**：以发布机构官网原文为准

### 解读质量控制
- **区分事实与判断**：政策原文内容是事实（引用原文），对用户的影响分析是判断（标注"分析认为"），两者要分开陈述
- **不确定标注"待核"**：对存疑或有歧义的条款解读明确标注，不得将推测说成结论
- **不过度解读**：政策没明确说的不脑补、不延伸，不把"鼓励方向"说成"强制义务"
- **引用具体条款**：每条要点尽量附上原文出处（条款号或章节名），方便用户回查

### 自检流程
- 政策解读完成后，须按 `references/quality-checklist.md` 逐项自检（来源权威性/时效性/准确性/完整性/解读客观性五维度）
- 检索执行与输出格式检查走 `references/retrieval-checklist.md`
- 重大政策或复杂条款建议交叉核对两个以上官方来源，确认一致后再输出

## 来源与引用规范

### 引用优先级
1. **国家法律法规**：法律、行政法规、国务院决定（最高效力）
2. **部门规章**：国务院组成部门发布的规章（以部令/局令形式发布）
3. **规范性文件**：各部委发布的通知、公告、意见等
4. **地方政策**：地方性法规、地方政府规章、地方规范性文件（仅适用于当地）
5. **行业指南与标准**：行业核算报告指南、国家标准、行业标准
6. **国际公约与标准**：UNFCCC、巴黎协定、ISO 标准等
7. **行业协会与第三方**：协会报告、研究机构数据（仅供参考，需注明非官方）

### 事实 vs 假设区分
- **事实**：政策原文条款、明确的量化要求、已发布的时间表 → 直引原文，标注文号和条款
- **判断/解读**：对政策影响的分析、趋势预判、合规建议 → 明确标注"分析认为"或"解读认为"，与事实分开
- **假设/推测**：基于政策方向的推演、情景分析 → 必须注明假设条件，不得当作确定结论呈现
- **不确定**：对存疑条款 → 标注"待核"，说明不确定性所在

### 引用标注要求
- **国家级政策**：发文机构 + 文号 + 标题，如《碳排放权交易管理办法（试行）》（生态环境部令第 19 号）
- **地方政策**：发布地区 + 发布机构 + 标题 + 发布日期，如《XX省碳达峰实施方案》（XX 省人民政府，2022 年 X 月）
- **行业指南**：《XX 行业温室气体排放核算方法与报告指南》（2022 修订版）
- **国际公约**：《巴黎协定》（UNFCCC，2015 年签署，2016 年生效）

完整的来源渠道与分类见 `references/standards-sources.md`，检索操作指引见 `references/source-guide.md`。

## 边界与免责

- 本 Skill 提供政策检索和解读支持，**不构成法律意见或合规保证**。
- 政策时效性强，解读基于检索时的最新公开信息，正式合规决策请以主管部门最新规定为准。
- 不提供涉及诉讼、行政处罚应对等需要律师资质的服务。
- 地方政策因地区差异大，具体适用请结合当地主管部门的实操口径。
- 征求意见稿、草案等非正式文件仅作趋势参考，不得作为合规依据。
