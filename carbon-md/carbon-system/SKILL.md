# Carbon System  企业碳管理体系建设

## Overview

为企业搭建系统化、可持续运营的碳管理体系，将核算、报告、目标、治理整合为常态机制。核心产出：管理框架 → 组织与治理 → 制度与流程 → 运行与评审。碳体系是其他各碳 skill（核算/合规/交易/ESG）在企业内落地的组织载体。

本 Skill 为**数据驱动模式**：体系设计与 MRV 流程所引用的**核算标准版本、行业核算规则、合规义务与政策依据**一律从 `data/` 数据层动态查询，不在本文件写死标准编号/年份/政策文号；历史值已下沉到 `references/`（并加注"以数据层为准"）。

## 数据层（体系设计前必读）

体系设计与 MRV 流程所引用的**核算标准版本、行业核算规则、合规义务与政策依据**一律从 `data/` 数据层动态查询，**不在本文件写死标准编号/年份/政策文号**。新增行业或标准换版只需在数据层更新。

| 内容 | 数据文件 | 统一查询命令 |
|---|---|---|
| 行业规则表（行业特点、MRV要求、核查要求） | `data/industry/industry_rules.json` | `python data/scripts/query_data.py get-industry <行业名>` |
| 政策元数据表（碳管理体系政策、核算标准） | `data/policy/policy_metadata.json` | `python data/scripts/query_data.py search-policy <关键词>` |
| 数据版本号 | — | `python data/scripts/query_data.py version` |

> 运行路径：在 `carbon-md/` 根目录下执行上述命令。

数据状态约定：数据层每条记录含 `confidence` 或 `status` 字段。ISO 14064 / ISO 14001 / ISO 50001 等国际管理体系框架本身数据层未收录，仍以 `references/standards-sources.md` 为背景参考并标注版本以官方最新为准；但**国标换版、行业核算指南、碳市场合规义务**必须查数据层。
## Workflow

### 1. 诊断对象与行业（数据驱动起点）
- 评估企业现状：排放源、现有管理、合规义务、披露需求。
- 确定主体**所在行业**、规模、报告期年份与地区，作为体系设计与标准匹配的输入。

### 2. 从行业规则表查询行业核算规则与合规状态（get-industry）
- 执行 `python data/scripts/query_data.py get-industry <行业名>`，获取该行业：核算标准（GB/T 编号及版本）、纳入碳市场时间/状态、配额分配方法、是否覆盖间接排放、核查机构要求、MRV 要求等。
- 用于确定体系 MRV 流程须对接的行业口径与核查义务；行业不在表中时提示"该行业规则未建立/未纳入碳市场"，体系按通用口径（GB/T 32150）设计并标注。

### 3. 从政策元数据表查询体系/核算标准版本与上位依据（search-policy）
- 执行 `python data/scripts/query_data.py search-policy ..., 政策类型=国家标准/核算指南/行政法规..., 适用行业=...)`，获取：
  - 通用核算通则的**现行有效版本**（如 GB/T 32150-2025，及其代替关系）；
  - 行业配套核算/核查指南文号与日期；
  - 体系合规上位依据（如《碳排放权交易管理暂行条例》国务院令775号）。
- 记录文号、发文机关、发布/施行日期、时效状态、数据状态；未命中不得编造，改用 `references/standards-sources.md` 历史索引并标注"待核"。

### 4. 组织、治理与制度文件编制
- 明确碳管理组织：决策层（如碳管理委员会）、执行层、岗位职责；建立跨部门协作（财务/生产/采购/战略）。
- 用 `references/system-guide.md` 编制碳管理制度文件：管理手册、程序、记录；数据采集与 MRV 流程按第 2–3 步查询到的行业口径与标准版本设定。
- 衔接各 skill 能力：核算（`carbon-accounting`）、合规（`carbon-policy`）、目标（`carbon-roadmap`）、披露（`carbon-esg`）。

### 5. 运行、监测与评审
- 建立排放数据采集、报告、评审的常态化流程（与 MRV 一致）；设定 KPI 与年度目标并纳入绩效考核。
- 定期管理评审：目标达成、数据质量、合规义务变化（关注数据层政策更新）、改进机会。
- 交付：制度文件走 `word`，职责/流程表走 `sheet`，体系架构配合 `doubao-visualization`。

### 6. 输出标注（必做）
- 在制度文件与方案中标注：体系引用的**核算/管理标准版本**（国标+ISO 方向）、**行业核算规则**（来自行业表，含数据状态）、**政策依据的文号与日期**（来自政策表）、数据状态（已查证/估算/占位-待核实/待核）。

## 规范
- 体系设计与企业规模、行业、合规要求匹配，不照搬模板；标准版本以数据层查询结果为准。
- 制度文件须可执行、职责明确；数据流程与 MRV（`carbon-mrv`）一致。
- 不编造管理记录；制度推行需与企业实际结合。

### 质量保证与数据规范
- **领导参与原则**：碳管理体系必须有最高管理层的承诺与参与，否则难以跨部门推动和持续运行。
- **体系适配原则**：体系设计与企业规模、行业、排放体量、合规义务相匹配，避免大企业用简易模板、小企业搞复杂体系。
- **协同融合原则**：与现有 ISO 14001 / ISO 50001 / 质量 / 安全等管理体系有机融合，不重复建设、不搞"两张皮"。
- **PDCA 闭环原则**：体系遵循"策划—实施—检查—改进"循环，有内部审核、管理评审与持续改进机制。
- **数据驱动原则**：碳管理以数据为基础，数据采集、质量控制、报告流程与 MRV 体系衔接一致；所引用核算标准与排放因子版本以 `_data` 数据层为准。
- 完成体系建设或制度文件编制后，应使用 `references/quality-checklist.md` 逐项自检，通过后方可发布运行。

### 来源与引用规范
- 引用的标准、法规、指南均需标注发布机构、文件名称、文号与年份（优先取自政策元数据表/行业规则表）。
- **已发布制度**与**推荐做法**严格区分，推荐性做法标注"建议"或"参考"，不表述为强制要求。
- 引用优先级：国家标准（GB/T / ISO 转化，数据层现行有效版本）> 部委规章与规范性文件 > 行业标准 > 行业协会指南 > 咨询机构最佳实践。
- 不同行业、不同层级（央企 / 地方国企 / 民企）的碳管理要求差异较大，应结合企业实际选择适用依据。
- 标准与数据来源的详细清单参见 `references/standards-sources.md`（历史参考，以数据层为准）。

### 边界与免责
- 本 Skill 提供碳管理体系建设的方法论与框架指导，不替代企业实际的体系运行与持续改进工作。
- 本 Skill 不构成法律、合规或管理咨询的专业意见，体系运行的有效性取决于企业实际执行情况。
- 本 Skill 不对企业碳管理体系能否通过第三方认证或满足特定客户要求做保证。
- 碳管理体系标准（如 ISO 38200 系列）仍在发展中，相关国际与国内标准可能更新，应跟踪最新进展（国标换版以数据层为准）。
- 涉及碳数据真实性、合规性、披露责任等法律问题，建议咨询专业法务与合规顾问。
